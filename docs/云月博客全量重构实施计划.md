# YunYueBlogs 全量重构实施计划（修订版）

> 文档状态：本地开发完成，待 Vercel Preview 验收
> 修订日期：2026-07-15
> 适用范围：公开博客 `YunYueBlog`、本地管理端 `my-blog-manager`、FastAPI 管理服务、GitHub 与 Vercel 发布链路

## 1. 计划目标

YunYueBlogs 继续采用“公开阅读站点 + 本地无代码管理端”的双应用结构，对公开博客的视觉、交互和内容交付进行全量重构，同时保留经过筛选的旧版功能。

本轮重构必须实现以下结果：

- 公开站具备稳定、快速、适合中文长文阅读的桌面端与移动端体验；
- 恢复旧版完整音乐能力，包括首页播放器、独立歌词区域、音乐详情页、其他页面悬浮播放器和跨页面连续播放；
- 恢复管理端图床配置、上传、媒体选择和外观资源管理，不再依赖手工填写图片 URL；
- 明确使用 Tailwind CSS 4、Motion for React、有限毛玻璃和高斯模糊，而不是只保留依赖名称；
- 修正首页 `Field note`、关于页作者档案、GitHub 图标和页脚 RSS 等当前视觉问题；
- 继续支持内容编辑、配置、同步、中文 Git 提交、推送 GitHub 和 Vercel 自动部署；
- 保证文章、杂谈、说说及旧 URL 在迁移前后可核对、可回退。

当前内容基线为 19 篇文章、1 篇杂谈和 1 条说说。迁移过程中不得在校验完成前删除旧内容目录。

## 2. 当前基线与问题审计

### 2.1 已建立的重构基线

- 公开博客已迁移至 Astro 7、React Islands 和 Tailwind CSS 4；
- 管理端使用 Next.js 16，管理服务使用 FastAPI；
- 文章、杂谈和说说已接入 Astro Content Collections；
- 项目、相册、友链和站点公开配置已改为结构化 JSON；
- Giscus、Bangumi、AI、音乐代理、同步计划和发布任务已有初步实现；
- 首页横版主视觉使用《星辰落笔时》；
- 文章默认封面使用《宁静星夜的魔法书房》；
- 已删除不再使用的原生成主视觉图。

### 2.2 本次审计确认的问题

- 当前 `MusicDock` 在组件内部创建 `Audio`，页面导航会销毁音频实例，不能满足跨页面连续播放；
- 当前 `/music` 只是播放器说明页，旧版歌词、歌单、播放模式和完整控制能力没有迁移；
- 图床后端和旧上传组件仍存在，但新管理端只暴露图床地址、名称和 Token，完整媒体工作流未接入新导航；
- Tailwind CSS 4 在公开站的实际职责不清晰，公开站尚未接入 Motion for React；
- 首页 `.home-note` 使用 `min-height: 100%`，被两行文章卡片拉伸，形成大片无信息空白；
- 关于页作者档案没有在右侧白色区域中光学居中；
- GitHub 链接错误使用代码图标 `CodeXml`，没有使用 GitHub 品牌图标；
- 页脚公开展示 RSS 图标缺少必要性说明。

## 3. 总体技术架构

### 3.1 公开博客

- 使用 Astro 7 负责静态页面、内容集合、路由、RSS、Sitemap、SEO 和按需服务端接口；
- 使用 Tailwind CSS 4 负责设计 Token、响应式布局、状态变体、模糊和减少动画降级；
- 使用 React Islands 承载音乐、搜索、AI、Bangumi 筛选、评论延迟加载和复杂抽屉；
- 使用 Motion for React，即 Framer Motion 的现行 React 包，处理导航、播放器、抽屉和模态框动效；
- 使用 Astro Vercel Adapter 部署，保留静态优先和按需服务端代理；
- 使用 Pagefind 提供构建期静态搜索，不引入常驻搜索服务。

### 3.2 本地管理端

- 使用 Next.js 16 和 React 19 构建本地控制台；
- 使用 FastAPI 提供文件、图床、同步、Git 和任务接口；
- 使用 Pydantic 校验所有接口输入和输出；
- 使用本地忽略目录 `workspace/` 保存内容、草稿、结构化数据、发布记录和私密配置；
- 管理端仓库只提交程序代码和必要文档，不提交用户文章、生成数据和本地密钥。

### 3.3 仓库和部署边界

- 保持公开博客和管理端两个 Git 仓库；
- 管理端将受管内容同步到公开博客仓库；
- 发布路径固定为“本地预览 → 同步差异确认 → GitHub 源码仓库 → Vercel Preview → 生产部署”；
- 删除 GitHub Pages 双轨发布；
- 禁止自动执行 `reset`、强制推送或覆盖未知目录。

## 4. 视觉与体验方向

### 4.1 设计定位

整体方向调整为“二次元个人编辑部 + AI 技术终端 + 私人音乐电台”。人物设定中的深蓝、奶白、灰紫和金色用于品牌识别，公开阅读区域仍以纸白、墨黑为主，珊瑚红与青绿作为双强调色。

设计不得退回通屏紫蓝渐变、全局玻璃卡片和重型粒子背景。音乐区域可以使用深墨玻璃与封面色彩，但必须与文章阅读区域形成清晰层级。

### 4.2 视觉约束

- 卡片圆角不超过 8px，除头像、唱片和明确需要圆形表达的控制；
- 不使用装饰性渐变球、模糊光球或无内容的大面积卡片；
- 页面分区使用留白、边线、排版和色块建立层次，不把所有内容装入卡片；
- 中文正文优先保证行长、行高、标题换行、代码块和表格可读性；
- 所有固定控件设置稳定尺寸，避免图标、加载态或长文本导致布局跳动；
- 移动端不得出现播放器、AI、底部导航和页面内容互相遮挡。

### 4.3 主视觉资产

- 首页主视觉固定使用《星辰落笔时》的横版优化文件；
- 文章无封面时使用《宁静星夜的魔法书房》；
- 作者头像使用云月人物设定头像或管理端配置的图床资源；
- 关键 LCP 主视觉默认保存在公开仓库并由 Vercel 分发；
- 相册、头像、普通背景和正文图片优先使用图床及缩略图。

## 6. 音乐系统

### 6.1 状态和音频生命周期

- 在公共 `BaseLayout` 中只挂载一个持久化 `MusicProvider`；
- 全站只允许存在一个 `HTMLAudioElement`，首页、音乐页和悬浮播放器共享同一状态；
- 启用 Astro `ClientRouter`，播放器岛使用 `transition:persist` 保留组件和音频状态；
- 保存当前曲目、队列、播放进度、音量、静音和播放模式；
- 使用 `sessionStorage` 恢复会话状态，但不绕过浏览器策略自动发声；
- 浏览器发生完整刷新时恢复曲目和进度，等待用户操作后继续播放；
- 监听媒体会话、可见性和音频错误，避免重复播放和状态失真。

参考：[Astro 视图过渡与状态持久化](https://docs.astro.build/en/guides/view-transitions/)。

### 6.2 首页音乐板块

- 首页主视觉和最近更新之后设置完整音乐板块；
- 左侧显示封面、歌曲、歌手、进度、时间、播放模式、上下曲、音量和播放按钮；
- 右侧或下方设置独立歌词区域，不把歌词塞进歌曲名称文本；
- 当前歌词突出显示，相邻歌词降低对比度；
- 提供“进入音乐详情页”入口；
- 首页不显示重复悬浮播放器。

### 6.3 音乐详情页

- 桌面端采用双栏：左侧唱片和完整控制，右侧“歌词 / 歌单”分段切换；
- 移动端改为唱片、控制、歌词的上下布局，歌单使用底部抽屉；
- 支持列表循环、单曲循环和随机播放；
- 支持点击歌词跳转和点击歌曲切换；
- 封面可以生成低透明度高斯模糊背景，但必须使用遮罩保证文字对比度；
- 音乐页不显示悬浮播放器，只显示完整播放器。

### 6.4 其他页面悬浮播放器

- 除首页和音乐页外显示紧凑悬浮播放器；
- 展开后显示封面、歌曲、歌手、上下曲、播放、音量和当前歌词；
- 当前歌词位于播放器下方，限制单行或两行并提供省略；
- 桌面端停靠左下或右下，移动端位于底部导航上方；
- 根据安全区域和 AI 面板状态动态避让，不遮挡正文操作。

### 6.5 音乐接口和降级

- 音乐源采用网易云与酷狗双源模式，公开配置统一保存为带 `source`、`id` 和显示元数据的 `musicTracks`；
- 网易云歌曲继续使用数字 ID，酷狗歌曲使用搜索结果中的 hash，管理端不要求用户填写或上传歌词文件；
- 逐字歌词按 `SearchLyricAsync(hash/name) → candidates(id, accesskey) → GetLyricAsync(fmt=krc) → DecodeLyrics → KrcParser` 自动获取；
- 网易云歌曲优先按歌曲名和歌手匹配酷狗 KRC，匹配失败时回退网易云 YRC/LRC；酷狗歌曲直接按 hash 获取音源和 KRC；
- KRC 的 `[language]` 数据自动拆分翻译和罗马音，音乐详情页允许切换显示；
- 管理端提供单曲歌词偏移，范围为 -5000 到 5000 毫秒，用于校准个别第三方音源的时间误差；
- 继续由 Vercel 服务端代理歌曲详情、音源和歌词，不向浏览器暴露签名参数或内部响应；
- 设置连接与读取超时、缓存和部分失败返回；
- 单首歌曲失败不阻断其余歌单；
- 对空歌词、纯音乐、超长歌词、重复时间戳和非法控制字符进行处理；
- 音源全部不可用时显示明确错误和重试，不创建空播放器；
- 第三方播放地址、版权和地区可用性不稳定，必须保留逐首失败提示和双源回退，不承诺永久可用；
- 音乐数据、歌词和播放器代码不得进入首页首屏主包。

## 7. 图床与媒体系统

### 7.1 管理端信息架构

“集成”页面只负责图床服务连接：“媒体与图床”页面负责资源操作，“外观”和各内容编辑器负责选择资源。

管理端需要提供：

- 图床名称、API 地址、公开地址规则和 Token 配置；
- 不上传文件的连接与认证测试；
- 拖放上传、文件选择、上传进度、取消和失败重试；
- 最近上传、搜索、复制链接、尺寸和格式查看；
- 统一媒体选择器，可返回头像、封面、背景、相册或正文图片；
- 上传成功后选择“仅保存资源”或“立即用于当前字段”；
- 图床未配置、Token 过期、网络超时和部分上传失败状态。

### 7.2 媒体数据契约

统一 `ImageAsset` 数据结构至少包含：

```ts
type ImageAsset = {
  id: string;
  url: string;
  thumbnailUrl?: string;
  width: number;
  height: number;
  bytes: number;
  mimeType: string;
  alt?: string;
  source: 'image-host' | 'local';
  createdAt: string;
};
```

公开 JSON 只保存可公开 URL 和图片元数据。图床 Token、原始接口响应和本机文件路径只能保存在 `LocalSecrets` 或本地发布记录中。

### 7.3 可配置资源

- 首页主视觉；
- 头像与 Favicon；
- 默认文章封面；
- 文章和杂谈封面；
- 正文插图；
- 相册封面和照片；
- 友链头像；
- 音乐页背景；
- 可选页面背景。

首页 LCP 主视觉默认使用本地文件。若用户选择图床主视觉，管理端必须提示性能影响并要求提供尺寸或响应式版本。

### 7.4 性能和安全

- 上传前校验 MIME、扩展名、大小和图片尺寸；
- 限制最大边长，生成 WebP/AVIF 或压缩后的 JPEG；
- 列表使用缩略图，灯箱和详情才请求原图；
- 所有图片输出宽高，使用懒加载和异步解码；
- 对图床域名设置允许列表、CSP 和预连接；
- 上传接口从服务端读取本机 Token，不让浏览器每次提交已有 Token；
- 校验用户提供的 URL，防止 SSRF、内网访问和危险协议；
- 图床不可用时使用本地头像和默认封面，不显示破图。

## 8. Tailwind、毛玻璃与动效

### 8.1 Tailwind CSS 4 职责

- 通过主题变量管理颜色、间距、阴影、圆角和断点；
- 用响应式工具类处理桌面、平板和移动布局；
- 使用 `supports-backdrop-filter` 提供模糊支持检测；
- 使用 `motion-safe` 和 `motion-reduce` 提供动画降级；
- 保留适合长文阅读的语义 CSS，避免把复杂排版全部写成长工具类字符串。

参考：[Tailwind CSS Backdrop Filter](https://tailwindcss.com/docs/backdrop-filter)。

### 8.2 Motion for React 职责

公开站新增 Motion for React，仅在 React Islands 中使用：

- 顶部导航收纳和展开；
- 移动端菜单和播放器抽屉；
- 歌词切换、歌曲切换和唱片状态；
- 搜索、AI 和模态框进入退出；
- 必要的共享布局指示器。

管理端继续复用现有 `framer-motion`。静态文章、归档和普通列表不为动画而水合。

参考：[Motion for React](https://motion.dev/docs/react)、[减少动态效果](https://motion.dev/docs/react-use-reduced-motion)。

### 8.3 顶部导航收纳动效

- 页面顶部显示完整品牌和主导航；
- 向下滚动超过阈值后收纳为紧凑导航条；
- 向上滚动时立即恢复主要导航；
- 使用 `transform` 和 `opacity`，不动画宽高造成布局抖动；
- 保持搜索、主题和菜单按钮始终可访问；
- 移动端维持稳定顶部栏和底部导航，不套用桌面悬浮岛形态；
- 减少动画模式下直接切换状态，不进行位移和弹簧动画。

### 8.4 毛玻璃和高斯模糊范围

毛玻璃仅用于：顶部导航、音乐播放器、移动抽屉、搜索、AI 面板和模态框。

高斯模糊仅用于：音乐封面背景、必要的遮罩背景和灯箱上下文。不得模糊正文、表单或整页内容。

桌面端同屏实时模糊表面原则上不超过 3 个；移动端降低模糊半径和透明叠层。浏览器不支持 `backdrop-filter` 时使用不透明背景和边框替代。

## 9. 首页布局修订

### 9.1 首屏

- 首屏直接展示站点名称、作者定位、最新内容入口和《星辰落笔时》；
- 桌面与移动分别设置合理裁切，人物主体不得被标题遮挡；
- 首屏高度必须露出下一节内容提示；
- 弹幕仅限主视觉，移动端、低性能设备和减少动画模式默认关闭。

### 9.2 最近更新与 Field note

最近更新改为 12 栏编辑布局，不再使用“左侧两行文章卡片 + 右侧等高空卡片”。

- 首篇文章获得更高视觉权重；
- 其他文章使用紧凑卡片或列表；
- 右侧编辑栏按内容自然高度排列；
- `Field note` 只展示最新杂谈标题、摘要和入口；
- 站点统计和最近说说作为独立信息段落填充右栏；
- 没有杂谈或说说时折叠对应段落，不保留占位空白；
- 移动端全部转为单栏，顺序为最新文章、Field note、更多文章。

### 9.3 首页后续内容

- 最近更新之后放置完整音乐板块；
- 项目、说说和 ACG 摘要按内容密度排序；
- 不在首页重复展示所有功能说明；
- 不使用无数据的大卡片维持所谓版式完整。

## 10. 关于页与页脚修订

### 10.1 关于页

- 使用 12 栏布局，正文约占 8 栏，作者档案约占 4 栏；
- 右侧白色区域使用网格或 Flex 完整居中；
- 作者档案内部设置最大宽度，头像、姓名、简介和联系方式整体光学居中；
- 长简介允许自然换行，按钮不得溢出；
- 移动端作者档案位于正文之后并改为紧凑横向或单栏布局。

### 10.2 图标和联系方式

- GitHub 使用官方单色 GitHub Mark，不再使用 `CodeXml`；
- 邮件继续使用 Lucide `Mail`；
- 品牌图标与通用操作图标分开管理；
- 图标按钮提供可访问名称和悬停提示。

### 10.3 RSS 决策

RSS 用于订阅和阅读器自动发现，因此继续保留 `/rss.xml` 与 `<head>` 中的 `rel="alternate"`。页脚不再显示可见 RSS 图标，避免把低频技术入口放进主要操作区。

页脚保留作者版权、GitHub、邮箱和备案信息。

## 11. 内容与数据契约

### 11.1 内容集合

使用 Astro Content Collections 建立 `Post`、`Chatter` 和 `Moment` 三套 Zod Schema。

- 保留现有文件名作为 slug；
- 统一日期格式并兼容旧日期；
- 支持空标签、中文路径和旧换行；
- 支持 GFM、数学公式、代码高亮、目录、图片和表格；
- 迁移前后核对文件数、slug、正文哈希和页面地址。

### 11.2 结构化数据

相册、友链、项目、公开站配置和媒体清单使用经过 Schema 校验的 JSON。管理端不再自动重写 TypeScript 源文件。

配置拆分为：

- `PublicSiteConfig`：公开站可以读取和发布的设置；
- `IntegrationConfig`：第三方服务的非敏感连接信息；
- `LocalSecrets`：图床 Token、AI Key 和本机 Git 凭据。

## 12. 评论、Bangumi、AI 与搜索

### 12.1 评论

- Gitalk 替换为 Giscus；
- 使用 GitHub Discussions，不保存 `clientSecret`；
- 未配置时显示“评论暂未开放”，不初始化空配置；
- 评论键由稳定页面路径生成并进行单元测试；
- 如需迁移旧 Issues，先生成路径映射报告再转换。

### 12.2 Bangumi

- `/bangumi` 只读展示个人收藏；
- 支持想看、在看、看过、搁置和抛弃筛选；
- 不做登录、写入、站内关注或社区内容复制；
- 服务端代理设置 User-Agent、超时、缓存、限流和空用户降级；
- Bangumi 排在音乐、图床和核心阅读体验完成之后实施。

### 12.3 AI 助手

- 使用按需打开侧边栏，不常驻遮挡页面；
- 服务端限制请求长度、超时、并发和频率；
- 日志不记录完整用户消息或密钥；
- 缺少 Key 时显示配置提示，不返回笼统网络错误。

### 12.4 搜索和 SEO

- 使用 Pagefind 静态搜索；
- 增加 RSS、Sitemap、OG 图片、规范链接和标签页；
- 音乐、AI 和评论不进入首屏主包；
- 所有页面提供唯一标题和描述。

## 13. 管理端产品结构

管理端导航调整为：概览、内容、媒体与图床、外观、集成、发布。

### 13.1 内容

- 统一文章与杂谈编辑模型；
- 支持自动保存、标签、封面、正文图片、预览和 Schema 校验；
- 支持提交中禁用、重复提交控制、失败恢复和未保存提醒；
- 说说、项目、相册和友链使用各自结构化表单；
- 列表覆盖加载、空数据、错误、搜索、筛选和长文本。

### 13.2 媒体与图床

- 提供图床状态摘要、上传区和媒体资源库；
- 相册和内容编辑器复用同一个媒体选择器；
- 资源删除只删除本地引用，远程删除必须单独确认；
- 对远程删除提供权限提示、二次确认和失败恢复。

### 13.3 外观

- 配置站点身份、头像、Favicon、首页主视觉和默认封面；
- 配置网易云/酷狗双源歌曲、音乐背景、单曲歌词偏移和播放器开关；
- 配置弹幕、导航收纳、模糊强度和减少特效选项；
- 提供桌面和移动预览；
- 所有设置进入同步差异，不直接修改公开仓库源码。

### 13.4 集成

- 配置 Bangumi、Giscus、图床和 AI；
- 密钥不回显，留空表示保留，清除需要明确勾选；
- 每项集成提供独立测试和错误信息；
- Vercel 环境变量与本机密钥分别提示，不宣称自动同步。

## 14. 操作队列、同步与发布

### 14.1 持久化操作队列

操作队列使用后端持久化的判别联合类型，覆盖内容、说说、项目、相册、友链、媒体引用、配置和删除操作。刷新页面后队列不得丢失。

队列任务必须支持：幂等标识、创建时间、状态、错误、重试次数和目标资源。

### 14.2 同步协议

- `POST /api/sync/plan`：生成差异、受管文件列表和警告；
- `POST /api/sync/apply`：按 `planId` 原子应用已确认差异；
- `POST /api/deploy/push`：生成中文提交信息并推送；
- `GET /api/jobs/{id}`：返回进度、阶段、结果和可恢复错误。

目标仓库必须通过真实路径、Git 根目录和项目标识三重校验。只允许删除受管清单中的过期文件，拒绝递归覆盖未知目录。

### 14.3 Git 安全

- 发布前检查公开仓库状态；
- 存在无关改动时中止并列出文件；
- 不执行自动 reset、force push 或覆盖；
- 提交信息必须为中文并允许用户编辑；
- 推送失败保留本地提交和任务记录，允许重试。

## 15. 接口、安全与隐私

- FastAPI 使用统一 `{ok, data, error}` 响应；
- 所有输入使用 Pydantic 校验并返回正确 HTTP 状态码；
- 外部调用设置超时、错误码、缓存、限流和有限重试；
- 不在日志、响应、注释或文档中输出 Token、Key 和 Git 凭据；
- 图床、AI 和 Git 密钥只保存在本地忽略目录或 Vercel 环境变量；
- 上传、导入、远程 URL 和外部响应全部视为不可信输入；
- 前端权限和校验不能替代后端约束。
