# 技术笔记：博客工程化

## 概述

一种通过内容交付、管理工作区和受控发布链路分离职责的 **博客工程化技术**。

其核心特征是：

- 使用 Astro 静态生成公开内容；
- 使用本地控制台维护内容和结构化数据；
- 使用被忽略工作区隔离草稿与密钥；
- 使用 GitHub 与 Vercel 形成单轨发布链路。

## 分类

所属分类：组件架构

## 核心技术内容

### 技术原理

公开站是可部署产物，管理端是本地写入工具，两者不能共享密钥边界。管理端把文章和配置写入 `workspace/`，发布时只把内容、公开 JSON 和受管清单同步到 Astro 仓库。

### 核心实现

```text
YunYueBlogs/
├── YunYueBlog/                 # Astro 公开站
│   ├── posts|chatters|moments/ # Markdown 内容
│   └── src/data/               # 公开 JSON
├── my-blog-manager/            # Next.js + FastAPI
│   └── workspace/              # 被忽略的本地数据
└── docs/                       # 架构与技术笔记
```

```text
编辑 -> workspace -> sync plan -> sync apply
     -> Git 中文提交 -> GitHub main -> Vercel
```

### 参数说明

| 参数 | 作用 | 推荐值 | 说明 |
|------|------|--------|------|
| `blogPath` | 发布目标 | Astro 仓库根目录 | 必须同时通过路径、Git 与项目标识校验 |
| `workspace/` | 本地数据源 | Git 忽略 | 保存内容、草稿、任务与私有配置 |
| `.yunyue-managed.json` | 受管清单 | 自动生成 | 限制后续可删除和可提交文件 |
| `site.json` | 公开配置 | Schema 校验 JSON | 不得包含 Token 或 Git 凭据 |
| Vercel 环境变量 | 服务端密钥 | 平台配置 | AI Key 不进入浏览器包 |

### 方案对比

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| 在线 CMS | 多设备编辑 | 需要账户、数据库和权限系统 | 团队内容平台 |
| 仓库内直接写作 | 结构简单 | 非技术操作成本高 | 纯开发者博客 |
| 本地控制台 | 密钥边界清晰、免代码操作 | 依赖本机环境 | 个人博客与私有工作流 |

### 设计要点

- 内容 slug 由文件名稳定生成；
- 结构化数据使用 JSON 与 Schema，不改写源码；
- 发布前检查目标仓库是否存在无关改动；
- 动态能力使用服务端函数，交互能力按需加载。

## 适用场景

- 个人博客需要本地可视化管理；
- Markdown 内容需要稳定 URL 与静态性能；
- 密钥和草稿不能进入公开仓库；
- 发布需要人工检查差异后再推送。
