# 技术笔记：操作队列

## 概述

一种通过暂存队列批量落盘并镜像到发布目录的 **操作队列技术**。

其核心特征是：

- 用 Context 保存待执行操作；
- 用操作类型路由到不同后端接口；
- 用白名单控制可同步目录和文件；
- 用同步前校验防止覆盖错误目录。

## 分类

所属分类：组件架构

## 核心技术内容

### 技术原理

管理端的设置、文章、相册、友链和弹幕修改不会立即写入发布端。前端先把操作加入 `OperationContext`，右上角工具箱统一展示待办。用户点击“更新本地”后，`Navbar` 根据操作类型调用 FastAPI；点击“同步 Blog”后，`sync.py` 将管理端数据镜像覆盖到 `YunYueBlog`。

### 核心实现

```ts
addOperation({
  type: "CONFIG",
  label: `配置暂存：${label}`,
  description: `修改了系统的 ${label}`,
  payload: formData,
});
```

```ts
switch (op.type) {
  case "CONFIG":
    apiUrl = `${apiBase}/api/config/update`;
    body = { updates: op.payload };
    break;
  default:
    apiUrl = `${apiBase}/api/drafts/sync_local`;
    body = { operations: [op] };
}
```

```py
SYNC_DIRS = ["posts", "chatters", "moments"]
SYNC_FILES = [
    "app/about/about.md",
    "data/albums.ts",
    "data/friends.ts",
    "data/projects.ts",
    "siteConfig.ts",
]

def is_safe_blog_dir(target_path):
    return os.path.exists(os.path.join(target_path, "package.json"))
```

### 参数说明

| 参数 | 作用 | 推荐值 | 说明 |
|------|------|--------|------|
| `operations` | 前端暂存队列 | 内存状态 | 用户确认后再落盘 |
| `type` | 操作分类 | `CONFIG` 等 | 决定调用哪个后端接口 |
| `payload` | 实际数据 | 结构化对象 | 避免字符串拼接配置 |
| `blogPath` | 同步目标目录 | 发布端根目录 | 必须通过安全校验 |
| `SYNC_FILES` | 文件白名单 | 显式列出 | 避免全目录误覆盖 |

### 设计要点

- 所有修改先进入队列，用户能看到、撤销或批量执行；
- 同步目标必须包含 `package.json`，降低误选目录的风险；
- 文章类目录采用镜像覆盖，配置类文件采用精确复制；
- 同步 `siteConfig.ts` 时跳过 `picBedToken`，避免敏感信息进入发布端。

## 适用场景

- 管理后台需要“先暂存、后执行”的工作流；
- 本地数据需要同步到另一个前端项目；
- 配置项较多且需要集中提交时；
- 非技术用户需要免代码维护博客时。

## 注意事项

- 镜像同步会覆盖目标目录中的旧文章和配置，执行前必须确认 `blogPath`；
- 队列保存在前端内存中，刷新页面会丢失未提交操作；
- 后端接口失败时应停止后续操作并提示具体失败原因。
