# 技术笔记：Giscus 评论

## 概述

一种通过 GitHub Discussions 保存评论并按页面路径建立主题映射的 **Giscus 评论技术**。

其核心特征是：

- 使用公开仓库与分类标识初始化组件；
- 使用稳定页面路径作为 Discussion 映射键；
- 使用懒加载避免评论脚本进入首屏链路；
- 使用空配置降级阻止无效登录请求。

## 分类

所属分类：组件架构

## 核心技术内容

### 技术原理

Giscus 通过 GitHub Discussions 保存评论。站点只需要公开的仓库 ID 与分类 ID，不需要把 OAuth `clientSecret` 发送到浏览器，也不需要维护 token exchange 代理。文章使用 `commentKey` 或当前路径建立稳定映射。

### 核心实现

```ts
const configured = Boolean(
  config.repo && config.repoId && config.categoryId
);

if (!configured) {
  return "评论暂未开放";
}
```

```ts
Object.assign(script.dataset, {
  repo: config.repo,
  repoId: config.repoId,
  category: config.category,
  categoryId: config.categoryId,
  mapping: "specific",
  term: commentKey,
  loading: "lazy",
});
```

### 参数说明

| 参数 | 作用 | 推荐值 | 说明 |
|------|------|--------|------|
| `repo` | Discussions 仓库 | `owner/repo` | 仓库必须启用 Discussions |
| `repoId` | GitHub 仓库标识 | 配置页生成 | 公开标识，不是密钥 |
| `categoryId` | 评论分类标识 | 配置页生成 | 迁移后保持稳定 |
| `commentKey` | 页面映射键 | 规范化路径 | 重命名 slug 时需要映射报告 |
| `loading` | 加载策略 | `lazy` | 降低首屏脚本成本 |

### 错误排查

| 现象 | 原因 | 处理 |
|------|------|------|
| 显示“评论暂未开放” | 配置不完整 | 在管理端“集成”补全公开标识 |
| 组件无内容 | Discussions 或 Giscus App 未启用 | 检查仓库设置与 App 权限 |
| 评论映射到错误主题 | 路径或 `commentKey` 变化 | 固定映射键并生成迁移表 |
| GitHub 登录不可用 | 网络或 GitHub 会话异常 | 保留正文阅读，稍后重试评论 |

旧版截图中的 `Error: Network Error` 来自 Gitalk 在空 OAuth 配置下仍初始化并请求 GitHub。2.0 在配置为空时不加载 Giscus 脚本，因此不会再发起这类无效请求。

## 设计要点

- 配置校验发生在渲染评论脚本之前；
- 评论失败不影响正文、搜索或导航；
- 明暗主题变化通过 Giscus 消息接口同步；
- 旧 Issues 迁移前先核对路径与 Discussion 映射。

## 适用场景

- 公开内容站希望复用 GitHub 身份体系；
- 评论量较小且不需要自建审核数据库；
- 站点需要避免保存 OAuth Secret；
- 内容路径可以提供稳定映射键。
