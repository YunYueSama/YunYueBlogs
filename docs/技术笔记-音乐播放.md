# 技术笔记：双源音乐播放与 KRC 动感歌词

## 概述

YunYueBlogs 的音乐系统使用“网易云 + 酷狗”双源模型。控制台统一维护歌曲引用，Astro 服务端按来源解析歌曲信息、播放地址和歌词，浏览器只接收规范化结果。正常使用不需要上传 YRC、KRC 或 QRC 文件。

系统保留全站唯一的 `HTMLAudioElement`。首页播放器、音乐详情页和其他页面的悬浮播放器通过同一个持久 React Island 共享曲目、进度和播放模式，Astro 页面切换不会中断播放。

## 分类

所属分类：服务端集成、媒体播放、时间轴渲染

## 双源数据模型

公开配置使用 `musicTracks` 保存最多 12 首歌曲：

```ts
type MusicTrackReference = {
  source: 'netease' | 'kugou';
  key: string;       // netease:1809646618 或 kugou:D895...1395
  id: string;        // 网易云数字 ID 或酷狗 32 位 hash
  name?: string;
  artist?: string;
  albumAudioId?: string;
};
```

旧的 `musicIds` 在读取时自动迁移为网易云引用，保存时仍生成兼容字段，避免已有工作区和部署配置突然失效。管理端按来源提供两种录入方式：网易云直接查询 ID，酷狗按关键词搜索后选择候选歌曲。

## 在线 KRC 获取链路

动态歌词实现参考本机 `D:\Work\Projects\KugouMusic.NET` 的职责拆分，实际链路为：

```text
SearchLyricAsync(hash/name)
  -> candidates(id, accesskey)
  -> GetLyricAsync(fmt=krc)
  -> DecodeLyrics(base64 + krc1 XOR + zlib)
  -> KrcParser
```

1. 已有酷狗 hash 时直接进入歌词搜索；网易云歌曲先按“歌名 + 歌手”搜索酷狗歌曲，再用标题、歌手和时长选出完整版本的真实 hash。
2. `SearchLyricAsync` 使用歌曲 hash 搜索歌词，不把网易云或酷狗歌曲响应中的 `Audioid` 误作歌词接口的 `album_audio_id`。
3. 从候选结果中选择匹配度最高且带有 `id`、`accesskey` 的记录，同时校验候选时长与音频时长。
4. `GetLyricAsync` 指定 `fmt=krc` 下载 Base64 内容。
5. `DecodeLyrics` 解码 Base64，校验 `krc1` 头，循环异或酷狗密钥后使用 zlib 解压。
6. `KrcParser` 把 `[start,duration]<offset,duration,0>文字` 转成行、字的绝对时间轴。
7. 解析后检查最后一行歌词结束时间，覆盖不足歌曲时长 70% 的结果视为试听版或错误候选并拒绝使用。
8. KRC 的 `[language:...]` 元数据自动拆出翻译和罗马音，音乐页按标签切换显示。

网易云歌曲通过上述精确 hash 解析自动组合“网易云音源 + 酷狗逐字歌词”。匹配不到完整 KRC 时，系统依次回退网易云 YRC 和普通 LRC；酷狗歌曲按 hash 同时解析播放信息和 KRC。歌手名、歌曲名或时长不一致的同名翻唱、试听片段不会覆盖当前歌曲的歌词。

## 时间控制

解析层输出绝对时间，渲染层只读取媒体时钟，不用固定定时器猜测歌速：

```ts
const currentMs = audio.currentTime * 1000 + track.offsetMs;
const progress = clamp((currentMs - word.startMs) / word.durationMs, 0, 1);
requestAnimationFrame(paintActiveLyricLine);
```

活动歌词行使用 KRC/YRC 的逐字开始时间和持续时间计算填色。普通 LRC 没有逐字时间，只能在相邻行之间估算，不能伪装成精确同步。管理端提供 -5000 到 5000 毫秒的单曲偏移，用于修正个别音源版本、前奏或第三方响应造成的整体误差。

## 服务端聚合

公开站 `/api/music` 接收 `tracks` JSON 参数，也兼容旧的 `ids` 参数。每首歌独立加载并返回统一结构：

```ts
type Song = {
  id: string;
  source: 'netease' | 'kugou';
  name: string;
  artist: string;
  cover: string;
  url: string;
  lrc: string;
  translation?: string;
  romanization?: string;
  lyricFormat: 'lrc' | 'yrc' | 'krc' | 'qrc';
  lyricSource: 'kugou-krc' | 'netease' | 'local-override' | 'none';
  offsetMs: number;
};
```

单首歌曲失败只在该结果上返回错误，不阻断歌单其余歌曲。歌词搜索、下载和播放信息均设置超时与内存缓存；服务端限制曲目数量、字段长度和响应体大小，浏览器不会接触酷狗签名盐或内部响应。

网易云歌曲会先请求播放器地址接口，不能播放时再使用歌词匹配阶段得到的精确酷狗 hash 尝试同曲播放源。两个来源都因版权、付费或地区限制不可用时，歌曲仍保留在歌单位置并标记为“暂不可播放”，但不会进入自动切歌队列。播放器只把 `NotAllowedError` 解释为浏览器自动播放限制；网络、解码和无支持音源使用各自的错误提示。

## 播放状态

- 全站只创建一个音频实例，多个 Portal 视图共享同一状态；
- 播放进度以较低频率更新 React 状态，活动行填色由 `requestAnimationFrame` 单独刷新；
- 首页和音乐页展示完整播放器，其他页面显示紧凑悬浮播放器；
- 页面切换通过持久 Island 保留音频对象，完整刷新时仅恢复曲目和进度，不绕过浏览器自动播放策略；
- 音乐详情页用歌词容器与活动行的实际边界计算滚动位置，并按容器高度提供动态首尾留白，使第一行、最后一行和中间歌词都能落在可视区域中心；
- 翻译与罗马音是显示层变体，不改变原歌词的时间轴。

## 管理端能力

- 查询网易云歌曲 ID；
- 搜索酷狗关键词并保存 hash；
- 混合排序、删除和可用性检查；
- 自动显示 KRC 是否可用、是否包含逐字时间；
- 保存单曲歌词偏移；
- 发布时把 `musicTracks` 与偏移配置同步到公开仓库。

管理端展示 `SearchLyricAsync -> candidates -> GetLyricAsync -> DecodeLyrics -> KrcParser` 状态链，歌词内容本身不写入公开站点配置。内部仍允许本地应急覆盖，但它不是正常工作流，也不要求用户维护歌词文件。

## 注意事项

- 酷狗和网易云的非公开网页接口可能调整，第三方音源也受版权、地区和网络策略影响；
- 酷狗播放 URL 可能是短时地址，必须在服务端按需刷新并缓存，不能永久写入配置；
- 不同平台的同名歌曲可能是翻唱、现场版或剪辑版，自动匹配后仍应检查歌手和时长；
- KRC 有真实逐字时间，普通 LRC 只有行时间；两者的同步精度不能等同；
- `/api/music` 依赖 Astro Vercel Adapter 或等价服务端运行环境，纯静态托管无法执行双源代理；
- 浏览器自动播放策略可能阻止未交互播放，这是预期行为。

## 验证重点

- 网易云歌曲能自动匹配酷狗 KRC，匹配失败后正确回退；
- 酷狗歌曲能按 hash 获取播放地址和逐字歌词；
- KRC 解密、翻译和罗马音拆分结果正确；
- 单曲失败不影响其他歌曲；
- 正负偏移同时作用于行和字时间；
- 桌面和移动端歌词不溢出，切页播放不中断。
