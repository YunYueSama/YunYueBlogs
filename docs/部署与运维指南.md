# 部署与运维指南

## 环境要求

| 工具 | 建议版本 | 用途 |
|------|----------|------|
| Node.js | 22 LTS 或兼容 Astro 7、Next 16 的版本 | 两个前端工程 |
| Python | 3.10 及以上 | FastAPI 与桌面启动器 |
| Git | 2.40 及以上 | 差异、提交和推送 |
| npm | 随 Node.js 安装 | 锁文件安装 |

## 公开站本地运行

```powershell
cd YunYueBlog
npm ci
npm run dev
```

生产验证：

```powershell
npm run lint
npm run test
npm run check
npm run build
```

`npm run build` 依次执行 Astro 类型检查、Vercel 产物构建和 Pagefind 索引生成。

## 管理端本地运行

```powershell
cd my-blog-manager
npm ci
python -m pip install -r requirements.txt
python -m uvicorn cms_core.main:app --host 127.0.0.1 --port 8000
npm run dev
```

在 `public/backend_config.json` 中写入本机 API 端口。该文件已被 Git 忽略，不应提交。Windows 桌面模式可运行 `Start.bat`。

管理端验证：

```powershell
npm run lint
npm run typecheck
npm run test:client
python -m pytest -q
npm run build
```

## Vercel 配置

公开博客仓库连接 Vercel 后使用自动识别的 Astro 构建设置。必须或可选的服务端环境变量如下：

| 变量 | 必需 | 默认值 | 用途 |
|------|------|--------|------|
| `DEEPSEEK_API_KEY` | 否 | 空 | Robin AI 的服务端密钥；为空时聊天不可用，小考仍可用 |
| `ROBIN_AI_API_KEY` | 否 | 空 | 兼容旧密钥配置，优先于 DeepSeek 密钥；接口与模型固定 |
| `BANGUMI_USERNAME` | 否 | 读取 `site.json` | 覆盖公开书架用户名 |

图床 Token、音乐账号凭据与 Git 凭据不得配置到公开 JSON。

## 发布流程

1. 在管理端“发布”中填写 Astro 博客仓库真实路径、remote 和目标分支；
2. 点击“生成差异预览”；
3. 若列出无关改动，先在博客仓库自行提交或处理，再重新预览；
4. 检查新增、更新与删除清单后执行“应用同步”；
5. 填写不超过 120 字的中文提交信息；
6. 执行“提交并推送”，等待任务状态成功；
7. 在 Vercel Preview 检查桌面、移动端和旧 URL，再切换生产域名。

发布链路不会执行自动合并、工作区重置、强制推送或未知目录递归删除。

发布页同时提供三种仓库操作：

- “检查状态”只读取当前分支、工作区文件及领先/落后提交数；
- “刷新远程”执行受超时限制的 `git fetch --prune`，只更新远程引用；
- “安全更新本地”仅在工作区干净、当前分支匹配且历史未分叉时执行 `git merge --ff-only`。

存在未提交文件、当前分支不匹配或本地与远程已经分叉时，控制台会停止更新并列出原因。Vercel 仍由 GitHub 仓库集成触发；可在发布设置保存 `vercel.com` 项目地址，推送成功后从该入口检查真实构建状态。

## Bangumi 配置

只填写公开用户名，不保存 Token。服务端代理会发送项目标识 User-Agent，并对结果缓存 1 小时、陈旧结果保留 24 小时。用户名不存在、上游限流或超时会显示可恢复错误，不影响其他页面。

管理端“保存集成配置”只写入被忽略的 `workspace/data/site.json`，不会直接修改公开仓库或 GitHub。完整生效顺序为：

1. 在“集成”保存 Bangumi 用户名；
2. 进入“发布”生成差异预览，确认包含 `src/data/site.json`；
3. 执行原子同步后，本地公开博客生效；
4. 使用中文提交信息推送 GitHub，由 Vercel 自动构建线上版本。

若发布页提示目标仓库存在未提交改动，需先审查并提交当前开发内容。安全同步不会覆盖脏工作区，也不会执行 `reset` 或强制推送。

## 故障恢复

### 同步被锁定

运行以下命令查看目标仓库改动：

```powershell
git status --short
```

控制台不会代替用户清理这些改动。确认并自行提交后重新生成计划。

### 推送失败

- 检查 remote、分支和 SSH/HTTPS 凭据；
- 查看 `/api/jobs/{id}` 返回的失败信息；
- 已创建但未推送的本地提交保留在仓库中，可手动重试 `git push`；
- 不使用 `push --force` 处理分支分歧。

### 本地仓库无法更新

- 先查看发布页列出的脏文件，不要使用 reset 或 clean 清除本轮开发；
- 本地领先时先确认提交，再按正常发布流程推送；
- 本地落后且工作区干净时可使用“安全更新本地”；
- 同时领先和落后表示分支已经分叉，必须在终端中人工审查和合并。

### 线上回退

在 Vercel 中将生产别名切回上一份成功 Deployment；代码层对应回退到上一份已验证 Git 提交。回退不修改管理端 `workspace/`，因此内容仍可重新生成发布计划。

## 发布前检查

- 内容数量、slug 和正文哈希与迁移基线一致；
- 文章不加载第三方评论，Bangumi 空用户名有降级页面；
- 音乐单曲失败不影响其他歌曲；
- AI 缺少 Key、超时和限流返回正确状态；
- `1440x900` 与 `390x844` 下导航、正文和浮层无重叠；
- Vercel Preview 的 Lighthouse 达到项目性能目标。


## 本机音乐服务

桌面模式 `Start.bat` 自动安装 `my-blog-manager/services/music-gateway` 的锁定依赖（禁用依赖安装脚本），并以随机端口及随机认证密钥启动只监听回环地址的网关。音乐账号二维码和凭据不进入公开源码；需要服务端音源时，通过管理端配置 Vercel 私有环境变量。Windows 凭据采用当前用户 DPAPI，复制账号文件到另一用户或电脑后需要重新登录。

酷狗每日福利优先使用当前用户计划任务；权限不足时自动改用 HKCU 启动项下的专用 `YunYueMusicDaily-*` 后台 worker。退出酷狗或关闭自动开关会移除对应任务/启动项，worker 在下一轮检查退出。关机、用户未登录、离线及平台资格限制不能保证领取。提交领取前会保存意图，未确认的请求仅核实记录，避免盲目重发；只有平台记录确认才显示到账。

启动器退出只清理自身启动的桌面网关；每日 worker 使用独立网关和配置，文件锁及用户级进程互斥防止并发重复领取。排查接口变更时不要记录 Cookie、Token 或完整上游异常。公开歌单和个人试听始终保持隔离。
