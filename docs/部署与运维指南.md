# 部署与运维指南

首次搭建请按[仓库 README 的折叠指南](../README.md#从第一次启动到第一次发布)操作；[博客 README](https://github.com/YunYueSama/YunYueBlog#想自己搭一个也欢迎)包含仓库准备、个性化与 Vercel 首次部署。本页补充开发和故障排查。管理端运行在本机，Vercel 仅部署博客端。

## 环境要求

| 工具 | 建议版本 | 用途 |
|------|----------|------|
| Node.js | 22.12+ 的受支持版本 | 两个前端工程 |
| Python | 3.10 及以上 | FastAPI 与桌面启动器 |
| Git | 2.40 及以上 | 差异、提交和推送 |
| npm | 随 Node.js 安装 | 锁文件安装 |

## 公开站本地运行

```powershell
cd YunYueBlog
npm.cmd ci
npm.cmd run dev
```

生产验证：

```powershell
npm.cmd run lint
npm.cmd run test
npm.cmd run check
npm.cmd run build
```

`npm.cmd run build` 依次执行图片优化、Astro 类型检查、Vercel 产物构建和 Pagefind 索引生成。

## 管理端本地运行

推荐 Windows 桌面模式，启动器会配置端口并管理进程：

```powershell
cd my-blog-manager
npm.cmd ci
py -3 -m pip install -r requirements.txt
.\Start.bat
```

`py` 不可用时使用 Python 3.10+ 的 `python`。纯浏览器模式只用于本地开发，需要两个独立终端。在管理端目录，终端一启动 API：

```powershell
python -m uvicorn cms_core.main:app --host 127.0.0.1 --port 8000
```

另一个终端准备端口配置并启动前端：

```powershell
Set-Content -LiteralPath public/backend_config.json -Value '{"api_port":8000}' -Encoding ascii
npm.cmd run dev
```

打开 Next 输出的地址；若改 API 端口，同时更新配置。`public/backend_config.json` 已被 Git 忽略，不应提交。开发结束分别在两个终端按 `Ctrl+C`；桌面窗口自动清理进程的行为不适用于手工启动的开发终端。

管理端验证：

```powershell
npm.cmd run lint
npm.cmd run typecheck
npm.cmd run test:client
python -m pytest -q
npm.cmd run build
```

## Vercel 配置

Vercel 导入自己的独立博客仓库，Root Directory 使用该仓库根目录，Framework 选择 Astro，安装 `npm ci`、构建 `npm run build`，输出目录保留默认。生产分支通常为 `main`；不要将管理端仓库或静态 `dist` 作为完整博客部署。首次上线可不配置可选密钥。

获得正式 URL 后，更新 `astro.config.mjs` 的 `site` 与 `src/data/site.json` 的 `siteUrl`，提交并重新部署。域名 DNS 按 Vercel Domains 页当前提示设置。服务端环境变量在项目 Settings → Environment Variables 设置，Production 变量保存后需重新部署才能生效：

| 变量 | 必需 | 默认值 | 用途 |
|------|------|--------|------|
| `DEEPSEEK_API_KEY` | 否 | 空 | Robin AI 的服务端密钥；为空时聊天不可用，小考仍可用 |
| `ROBIN_AI_API_KEY` | 否 | 空 | 兼容旧密钥配置，优先于 DeepSeek 密钥；接口与模型固定 |
| `BANGUMI_USERNAME` | 否 | 读取 `site.json` | 覆盖公开书架用户名 |
| `NETEASE_MUSIC_COOKIE_JSON` | 否 | 空 | 网易云服务端账号，JSON 对象格式的私有 Cookie |
| `KUGOU_MUSIC_COOKIE_JSON` | 否 | 空 | 酷狗服务端账号，JSON 对象格式的私有 Cookie |

图床 Token、音乐账号凭据与 Git 凭据不得配置到公开 JSON。本机音乐登录不会自动上传服务端账号，当前管理界面没有音乐账号一键云端同步入口；账号环境变量属于可选进阶配置，不是基础部署前提。Cookie JSON 应为平台所需字段组成的对象，其值为字符串；错误、过期或缺字段时无法获取账号音源。不要分享真实值，也不要把加密本机登录文件直接填入变量。

管理端上传 Robin 密钥前需安装 Vercel CLI、执行 `vercel.cmd login`，并在本地博客目录执行 `vercel.cmd link` 关联已有项目。项目地址只用于跳转；`.vercel/` 绑定和 CLI 授权每台设备分别配置，均不提交。Robin 同步会重新部署服务器已有生产版本，内容改动仍须通过 Git 发布流程上线。

## 发布流程

1. 在管理端“发布”中填写 Astro 博客仓库真实路径、remote 和目标分支；
2. 首次使用先保存配置（点击“检查状态”），再点击顶部“从服务器同步并启用”，确认服务器文章与歌单正确；日常发布前刷新远程和服务器内容，必要时安全更新本地，然后点击“生成差异预览”；
3. 若列出无关改动，先在博客仓库自行提交或处理，再重新预览；
4. 检查新增、更新与删除清单后执行“应用同步”；
5. 填写不超过 120 字的中文提交信息；
6. 执行“提交并推送”，等待任务状态成功；
7. 在 Vercel 核对对应提交的部署已 Ready，并检查桌面、移动端及旧 URL。生产分支推送通常直接触发 Production；需要先验收 Preview 时应使用非生产分支，不把生产推送误认为仅预览。

发布链路不会执行自动合并、工作区重置、强制推送或未知目录递归删除。

发布页同时提供三种仓库操作：

- “检查状态”只读取当前分支、工作区文件及领先/落后提交数；
- “刷新远程”执行受超时限制的 `git fetch --prune`，只更新远程引用；
- “安全更新本地”仅在工作区干净、当前分支匹配且历史未分叉时执行 `git merge --ff-only`。

存在未提交文件、当前分支不匹配或本地与远程已经分叉时，控制台会停止更新并列出原因。Vercel 仍由 GitHub 仓库集成触发；可在发布设置保存 `vercel.com` 项目地址，推送成功后从该入口检查真实构建状态。

同步预览同时绑定目标仓库的提交与分支。预览后执行拉取、提交或切换分支，即使工作区仍干净，也需要重新生成预览。升级前生成的旧计划同样需要重新预览；本地内容不因此删除。

## Bangumi 配置

只填写公开用户名，不保存 Token。服务端代理会发送项目标识 User-Agent，并对结果缓存 1 小时、陈旧结果保留 24 小时。用户名不存在、上游限流或超时会显示可恢复错误，不影响其他页面。

管理端“保存集成配置”中的 Bangumi 用户名修改只写入被忽略的 `workspace/data/site.json`，不会直接修改公开仓库或 GitHub。完整生效顺序为：

1. 在“集成”保存 Bangumi 用户名；
2. 进入“发布”生成差异预览，确认包含 `src/data/site.json`；
3. 执行原子同步后，本地公开博客生效；
4. 使用中文提交信息推送 GitHub，由 Vercel 自动构建线上版本。

修改 Bangumi 用户名时会核对该页面读取的云端内容版本，旧表单需刷新后再保存。只修改图床地址、名称或密钥时不写公开站点配置，也不依赖远程仓库在线。API 调用方应仅在修改或清空公开用户名时提交 `bangumiUsername`；省略该字段表示保持公开用户名不变。

若发布页提示目标仓库存在未提交改动，需先审查并提交当前开发内容。安全同步不会覆盖脏工作区，也不会执行 `reset` 或强制推送。

## 故障恢复

### 同步被锁定

运行以下命令查看目标仓库改动：

```powershell
git status --short
```

控制台不会代替用户清理这些改动。确认并自行提交后重新生成计划。

### 推送失败

- 检查 remote、分支和 SSH/HTTPS 凭据；
- 查看 `/api/jobs/{id}` 返回的失败信息；
- 已创建但未推送的本地提交保留在仓库中，可手动重试 `git push`；
- 不使用 `push --force` 处理分支分歧。

### 本地仓库无法更新

- 先查看发布页列出的脏文件，不要使用 reset 或 clean 清除本轮开发；
- 本地领先时先确认提交，再按正常发布流程推送；
- 本地落后且工作区干净时可使用“安全更新本地”；
- 同时领先和落后表示分支已经分叉，必须在终端中人工审查和合并。

### 线上回退

在 Vercel 中将生产别名切回上一份成功 Deployment；代码层对应回退到上一份已验证 Git 提交。回退不修改管理端 `workspace/`，因此内容仍可重新生成发布计划。

## 发布前检查

- 内容数量、slug 和正文哈希与迁移基线一致；
- 文章不加载第三方评论，Bangumi 空用户名有降级页面；
- 音乐单曲失败不影响其他歌曲；
- AI 缺少 Key、超时和限流返回正确状态；
- `1440x900` 与 `390x844` 下导航、正文和浮层无重叠；
- Vercel Preview 的 Lighthouse 达到项目性能目标。


## 本机音乐服务

桌面模式 `Start.bat` 自动安装 `my-blog-manager/services/music-gateway` 的锁定依赖（禁用依赖安装脚本），并以随机端口及随机认证密钥启动只监听回环地址的网关。音乐账号二维码和凭据不进入公开源码；需要服务端账号音源时，另行配置 Vercel 私有环境变量；本机登录不会自动同步。Windows 凭据采用当前用户 DPAPI，复制账号文件到另一用户或电脑后需要重新登录。

酷狗每日福利在管理窗口运行期间检查领取资格；当前桌面启动器会停用旧版后台任务，关闭窗口后停止本次运行的本机服务。离线及平台资格限制不能保证领取。提交领取前会保存意图，未确认的请求仅核实记录，避免盲目重发；只有平台记录确认才显示到账。

Windows 本机账号凭据采用当前用户 DPAPI，另一用户或电脑需要重新登录。排查接口变更时不要记录 Cookie、Token 或完整上游异常。账号本机播放与公开博客的服务端账号配置需要分别验证。
