# 🏗️ 项目架构详解

本文档深入解析 YunYueBlogs 的整体架构设计，包括技术栈选型、系统分层、数据流设计等核心内容。

---

## 📐 整体架构

YunYueBlogs 采用**"三层四端"**架构设计：

```
┌─────────────────────────────────────────────────────────────┐
│                      用户终端层                              │
├─────────────┬─────────────┬─────────────┬─────────────────┤
│   PC 浏览器  │  手机浏览器  │   平板设备   │   桌面客户端    │
└─────────────┴─────────────┴─────────────┴─────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                      前端展示层                              │
├─────────────────────────────────────────────────────────────┤
│  YunYueBlog (Next.js 15 + React 19 + Tailwind CSS 4)       │
│  ├── 首页 (个人名片 + 音乐播放器 + 背景特效)                 │
│  ├── 文章页 (Markdown 渲染 + 评论系统)                       │
│  ├── 动态页 (碎碎念 + 时间线)                                │
│  ├── 友链页 (友人帐 + 留言板)                                │
│  ├── 项目页 (项目展示 + 仓库信息)                            │
│  └── 灵境页 (创意工坊 + RPG 等级系统)                        │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                      后端管理层                              │
├─────────────────────────────────────────────────────────────┤
│  my-blog-manager (FastAPI + PyWebView)                      │
│  ├── 内容管理 (文章/动态/说说 CRUD)                          │
│  ├── 配置管理 (siteConfig 读写同步)                          │
│  ├── 媒体管理 (图床上传 + 音乐管理)                          │
│  ├── 部署管理 (双轨部署 + Git 操作)                          │
│  └── 桌面客户端 (PyWebView 窗口)                             │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                      部署托管层                              │
├───────────────────────┬─────────────────────────────────────┤
│   A 线 (GitHub Pages) │   B 线 (Vercel)                     │
│   ├── 静态文件部署     │   ├── 源码自动构建                   │
│   ├── gh-pages 分支   │   ├── main 分支                     │
│   └── 自定义域名       │   └── Serverless Functions          │
└───────────────────────┴─────────────────────────────────────┘
```

## 🔧 技术栈选型

### 前端技术栈

| 技术 | 版本 | 用途 | 选型理由 |
|------|------|------|----------|
| **Next.js** | 15 | React 全栈框架 | SSR/SSG 支持、App Router、API Routes |
| **React** | 19 | UI 组件库 | 最新特性（Server Components、Concurrent） |
| **TypeScript** | 5.x | 类型安全 | 编译时类型检查、IDE 智能提示 |
| **Tailwind CSS** | 4 | 原子化 CSS | 快速开发、响应式设计、暗色模式 |
| **Framer Motion** | latest | 动画引擎 | 声明式动画、物理引擎、拖拽支持 |
| **Lucide React** | latest | 图标库 | 轻量级、Tree-shakable、风格统一 |

### 后端技术栈

| 技术 | 版本 | 用途 | 选型理由 |
|------|------|------|----------|
| **Python** | 3.10+ | 运行环境 | 广泛支持、丰富的库生态 |
| **FastAPI** | latest | Web 框架 | 高性能、自动文档、异步支持 |
| **Uvicorn** | latest | ASGI 服务器 | 高性能异步服务器 |
| **PyWebView** | latest | 桌面窗口 | 轻量级、跨平台、原生窗口 |
| **HTTPX** | latest | HTTP 客户端 | 异步支持、现代 API |

### 部署技术栈

| 技术 | 用途 | 优势 |
|------|------|------|
| **GitHub Pages** | 静态托管 (A 线) | 免费、稳定、自定义域名 |
| **Vercel** | 无服务器托管 (B 线) | 自动构建、边缘网络、Serverless |
| **GitHub Actions** | CI/CD | 自动化部署、免费额度充足 |

## 🎨 设计模式

### 1. 单一数据源模式

所有配置数据集中存储在 `siteConfig.ts`，前端和后端都从同一文件读取：

```typescript
// siteConfig.ts
const siteConfig = {
  title: "YunYue's Blog",
  description: "个人博客",
  social: { github: "https://github.com/..." },
  gitalkConfig: { ... },
  geminiConfig: { ... },
  // ...
}
```

### 2. 操作队列模式

配置修改不立即生效，而是暂存到队列中，用户确认后批量提交：

```typescript
// 用户修改 → 暂存队列 → 批量提交 → 同步部署
handleUpdate('title', '新标题')
pushToQueue('修改标题', 'title', '新标题')
// ... 其他修改
commitAll() // 一次性提交所有修改
```

### 3. 三层同步模式

```
本地管理端 → 博客目录 → 线上站点
    ↓           ↓           ↓
  保存文件    同步覆盖    Git 部署
```

### 4. 响应式组件模式

使用 Tailwind 断点实现响应式：

```tsx
<nav className="hidden md:block"> {/* PC 端导航 */}
<MobileNav className="block md:hidden" /> {/* 移动端导航 */}
```

## 🔌 接口设计

### 统一接口规范

所有 API 遵循 RESTful 设计：

| 方法 | 路径 | 用途 |
|------|------|------|
| GET | `/api/music?id=123` | 查询歌曲信息 |
| POST | `/api/chat` | AI 对话 |
| POST | `/api/picbed/upload` | 上传图片 |
| POST | `/api/sync` | 同步文件 |
| POST | `/api/deploy` | 部署站点 |
| GET | `/api/config` | 获取配置 |
| POST | `/api/config` | 更新配置 |

### 响应格式

```json
{
  "success": true,
  "data": { ... },
  "message": "操作成功"
}
```

错误响应：

```json
{
  "success": false,
  "error": "错误信息",
  "code": "ERROR_CODE"
}
```

## 🔒 安全设计

### 1. 敏感信息隔离

前端 `siteConfig.ts` 不包含图床 Token 等敏感信息，后端同步时自动过滤：

```python
# sync.py - 同步时过滤敏感字段
SENSITIVE_KEYS = ['picBedToken', 'clientSecret']
```

### 2. 环境变量管理

API Key 通过环境变量注入，不硬编码在代码中：

```typescript
const apiKey = process.env.GEMINI_API_KEY
```

### 3. 授权登录代理

GitHub OAuth 请求通过后端代理，避免前端暴露 Client Secret：

```typescript
// /api/github 代理 OAuth 请求
proxy: '/api/github'
```

## 📈 性能优化

### 1. 图片优化

- 使用 Next.js Image 组件自动优化
- 支持 WebP 格式
- 懒加载非首屏图片

### 2. 代码分割

- 动态导入非关键组件
- 路由级别代码分割

### 3. 缓存策略

- 静态资源长期缓存
- API 响应适当缓存

### 4. 动画性能

- 使用 CSS 动画而非 JavaScript
- 使用 `transform` 和 `opacity` 实现硬件加速
